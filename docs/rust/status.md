# Status

What the Rust `bench` does today, what it does not do yet, and how each part was checked. When a part's row says "not yet", the 0.8 Python CLI on this branch still has it (`uv run bench ...`).

## Task formats

| Format | State |
|---|---|
| task.md draft 2 | Native. The parser and checker are a port of task-md's reference checker (`tools/taskmd.py`), checked against its output on every example |
| BenchFlow 0.8 task.md (YAML frontmatter) | Read and checked; `bench import` converts it |
| Split layout (`task.toml`, schema 1.0 to 1.4) | Read and checked, with warnings for keys other runners ignore silently; `bench import` and `bench export` convert both ways |
| Terminal-Bench v1 (`task.yaml`, `run-tests.sh`, `docker-compose.yaml`) | `bench import` converts it through the split layout (checked on synthetic fixtures and 9 real tasks). `solution.yaml` is refused |

Fields the Rust runner reads but cannot honor yet are refused by name before a trial starts (`R401`), never skipped. Today that covers: wildcard hosts in a network allowlist or blocklist, `network = "none"` or an allowlist with a model agent (its own traffic to its model would be refused), rubric criteria judged by `agent`, `vlm`, `panel`, or a person (`llm` criteria are judged on the host: [rubrics.md](rubrics.md)), clocks, time zones, worlds, simulated users, roles, and per-output caps.

## Task runtime features

| Feature | How a task asks for it | Docker, Podman | Daytona |
|---|---|---|---|
| Stages graded one after another | The split layout's `[[steps]]` (`steps/<name>/`, `min_reward`, `multi_step_reward_strategy`); task.md stages with a `gate`, `outputs`, their own `agent`/`verifier` timeout, `ready`, `mounts`, or `stages/<name>/verifier/` and `oracle/` | Run | Run |
| A separate verifier's own image | `isolation = "separate"` (split layout: `environment_mode`) with `[verifier.sandbox] image` (split layout: `[verifier.environment] docker_image`) or `verifier/Dockerfile` (split layout: `tests/Dockerfile`) | Run | Run |
| Services beside the agent's container | The split layout's `environment/docker-compose.yaml`; task.md's `[[sandbox.services]]` or `[sandbox] compose = "sandbox/docker-compose.yaml"` | Run, on a private network | Refused by name |
| Hooks after the agent's turn, before grading | The split layout's `[[verifier.collect]]`; task.md's `[[verifier.snapshot]]` | Run | Run (in the agent's container; a hook in a service is refused with the services) |
| Package files mounted read-only | task.md's `[sandbox] mounts` and `[stages.<name>] mounts` | Run | Run |
| Artifacts manifest | Declared outputs (`artifacts`, `[sandbox] outputs`, a stage's outputs) | `artifacts/<save_as>` and `artifacts/manifest.json` | The same, including 0.8's rule that an output whose own `exclude` matches it (its name, or `.` for a folder, so `exclude = [".*"]`) captures nothing; `bench check` warns about it (`P015`) |
| GPU types | `gpu_types` | Checked with `nvidia-smi` in the sandbox; a mismatch refuses the trial | GPUs refused by name |

How each one works:

- **Stages.** Every stage runs in the same sandbox: the previous stage's verifier and solution are removed, the stage's files and mounts are placed (root stages the files in a folder of its own and the agent user copies them into the workdir, so root never writes through a link the agent left), the agent gets the stage's prompt and time, the handoff kills every agent process, the stage's outputs and hooks are collected, and the stage's verifier grades it (its own folder, else the task's; in the split layout, `steps/<name>/tests/` is layered over `tests/`). A missed gate stops the trial. The reward is each key's mean over the stages or the final stage's (`multi_step_reward_strategy`, `[verifier] combine_stages`); a stage never reached counts as 0 (task.md's default) or is left out (the split layout's rule). The oracle runs each stage's own solution, else the task's; `nop` does nothing; controls and probes run once per stage with `BENCHFLOW_STAGE` set; a model agent gets a fresh session per stage, unless `--resume-sessions` asks it to resume its own. Each stage leaves `steps/<name>/` (agent, trajectory, verifier, artifacts, hooks), and `result.json` holds `step_results` in the split layout's shape (`step_name`, `verifier_result.rewards`) with each gate's outcome.
- **A verifier image.** The image is chosen in task.md's order: the named image, then `verifier/Dockerfile` (built with that folder as its context), then the task's own image. BenchFlow 0.8 differs in one case, and a 0.8 frontmatter task keeps 0.8's order: with no verifier sandbox declared, 0.8 takes the task's prebuilt `docker_image` before `tests/Dockerfile`. The verifier's files are uploaded as well, as 0.8 does.
- **A separate verifier's sandbox.** It starts from the verifier's image and holds the verifier's files and the trial's saved outputs, restored at their own paths. The outputs archive is made by the image's own `tar`, which an agent that is or can become root controls, so before anything is saved or restored, BenchFlow copies it on this machine into a new archive that holds only regular files inside the task's outputs, folders strictly inside them, and hard links between such files, each with its setuid, setgid and sticky bits cleared and its modification time kept (0 for one that is negative, as from before 1970, or 2^33 seconds or more); anything else (links, special files, paths outside the outputs or with `..`, folders at or above an output, entries the verifier's `tar` would stop on, as far as the archive shows: an owner past 32 bits, a name with a NUL, a name longer than Linux allows (a part over 255 bytes, or 4,096 bytes or more), more than 128 path parts, an entry under a path kept as a file, a file at a path kept as a folder) is dropped and listed in `custody.json` (`outputs_refused`), and the trial is graded with the rest. So are files and hard links past 1 GiB plus 64 MiB in all, each name counted at its file's full size, as the pack counts them: a hard link costs nothing in the archive but a full copy wherever the outputs are unpacked. The same byte budget holds wherever an archive from the sandbox is unpacked on this machine (`outputs/`, a stage's outputs, the agent's session): what is past it is left out, never an error, and a failed unpack leaves no partial folder. `outputs/` and a later regrade get the same checked copy. A long name of 64 KiB or more, a PAX entry over 64 KiB, or more than 100,000 entries, makes the archive the sandbox's error (`R103`). After the restore, `/logs/verifier` is emptied, so nothing the archive held can stand for the verifier's result. It gets none of the task's mounts (`[sandbox] mounts`, a stage's `mounts`): a verifier that needs a mounted file must have it in its own image or its verifier folder. The outputs keep the owners and modes they had when they were packed, after the handoff, so files under the workdir arrive owned by root (the handoff gives the workdir to root before grading), and outputs from other folders keep the agent user's owners.
- **Services.** Each service starts from its own image (pulled, or built from its folder) before the agent's sandbox, and must pass its healthcheck before the next starts. They share an internal network the host has no address on: services have no internet, and nothing on the network can reach the host. The agent's sandbox keeps its own network and joins this one, where it reaches each service by name; with `network = "none"` the services are all it can reach. Their logs are kept in `services/<name>.log`, and they are removed with the trial. Compose files may use the split layout's template: the keys it puts on service `main` (the build, the image name, an idle command, the network mode, the log folders, CPU and memory limits) are what BenchFlow sets from the task, so they are ignored with a note (`P010`). An environment value read from the host is dropped with a warning (`P011`; `${VAR:-default}` becomes its default), and so is a bind mount of a host folder (`P012`). A `command` written as one string is split into words as Docker Compose splits it, with no shell: a string Compose refuses (an unclosed quote, a `(` outside quotes) is an error (`P014`), as it stopped the task under 0.8, and one Compose cuts at a shell operator (`>`, `|`, `;`, `&`, `<`) runs the words before it, with a warning (`P013`). Services take `image` or `build`, `command`, `environment`, `healthcheck`, `expose`, `networks`, and `depends_on`, with one plain bridge network; any other key is refused by name.
- **Hooks** run after every agent process is gone and before grading, as root unless they name a user, with the verifier's trusted `PATH`; each one's command, exit code, and output are in `hooks/<n>.txt`. A failing hook leaves the trial unscored (`R311`). task.md's spec runs a snapshot in a fresh container of the task's image with its `reads` paths on volumes; this runner runs it in the agent's own container, where those paths already are.
- **Mounts** are uploaded and made root-owned and read-only before the agent starts (a stage's when the stage unlocks); an agent running as root could still change them, and the trial's defenses say so.

Still refused by name within these features: a step's own settings other than its timeouts (a step's user, network, or env), a separate verifier for each stage, stages that unlock on a submitted file, outputs collected from a service, regrading a task graded in stages, and services or GPUs on Daytona.
